# ログインと端末間同期を有効にする

アプリの公開先は Cloudflare のままで、ログインと記録の保存先に Supabase を使います。パソコンに Node.js を入れる必要はありません。次の作業はブラウザーでできます。

この手順を完了するまでは、アプリは従来どおり端末内保存で使えます。「アカウントと同期」には準備中の案内が表示されます。既存の問題・学習記録を消す必要はありません。

## 1. Supabase プロジェクトを作る

1. <https://supabase.com/dashboard> を開き、アカウントを作成・ログインします。
2. **New project** からプロジェクトを作成します。名前は `focusgold` などで構いません。
3. データベースのパスワードを設定し、リージョンを選択して作成します。このパスワードは安全な場所に保管してください。アプリの設定やチャットへの入力は不要です。
4. プロジェクトの準備ができるまで待ちます。

プランの利用条件は作成画面で確認してください。Supabase の画面名は更新により多少異なる場合があります。

## 2. 学習記録を保存するテーブルを作る

1. GitHub の [SQL ファイル](https://github.com/4rle/math/blob/main/supabase/migrations/001_study_sync.sql) を開きます。
2. **Raw** を開くなどして、ファイルの内容をすべてコピーします。
3. Supabase のプロジェクトで **SQL Editor → New query** を開きます。
4. コピーした SQL を貼り付けて **Run** を押します。
5. エラーがなければ完了です。成功時に行データが表示されないことがあります。

この SQL は、ログインした本人だけが自分のデータを読めるルールと、同期用の保存処理を作ります。テーブルのセキュリティ設定（RLS）はオンのまま使います。同じファイルの再実行にも対応しています。

## 3. メール認証と公開 URL を設定する

1. Supabase の **Authentication** で **Email** によるサインアップを有効にします。
2. **Confirm email** を有効にして使ってください。新規登録時に確認メールを送ります。
3. パスワードの最小文字数を **12文字以上**に設定します。アプリの新規登録画面も12文字以上を要求します。
4. **URL Configuration** の **Site URL** に、Cloudflare で公開したアプリの URL を入力します。例：`https://あなたのプロジェクト.pages.dev`。
5. **Redirect URLs** にも同じアプリの URL の末尾に `/` を付けたものを追加します。例：`https://あなたのプロジェクト.pages.dev/`。

独自ドメインを使っている場合は、その実際の URL を指定してください。メールのリンクは、登録・再設定を申し込んだブラウザーで開いてください。別ブラウザーで開くと認証の引き継ぎに失敗することがあります。

確認メール・パスワード再設定メールは Supabase が送信します。標準のメール送信には宛先や回数などの制限があります。利用するメールアドレスへの送信が許可されているか確認し、一般利用者向けに公開する場合は **Authentication のメール送信設定（SMTP）** も設定してください。メールが届かない場合は迷惑メールと Supabase の認証ログ・送信設定を確認します。

## 4. 公開用の接続情報を確認する

Supabase の **Connect**、またはプロジェクト設定の **API / API Keys** で次の2つを確認します。

| 必要なもの      | 値の例                         |
| --------------- | ------------------------------ |
| Project URL     | `https://xxxxxxxx.supabase.co` |
| Publishable key | `sb_publishable_...`           |

旧形式の **anon / public** キーも使えます。

**`service_role` キー、`sb_secret_...` キー、データベースのパスワードは使いません。** これらを GitHub やブラウザーに公開しないでください。今回使う Publishable key は公開用で、保存データのアクセス制御は認証と RLS が行います。アプリのビルドも、認識できる秘密キーの指定を拒否します。

## 5. Cloudflare に設定する

Cloudflare の公開済みプロジェクトを開き、**Settings → Environment variables / Variables and Secrets** などの設定画面で次の2つを追加します。

| 変数名                          | 入れる値                |
| ------------------------------- | ----------------------- |
| `VITE_SUPABASE_URL`             | 手順4の Project URL     |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | 手順4の Publishable key |

- Cloudflare **Pages**：本番（Production）の **ビルド時の環境変数**に設定します。
- Cloudflare **Workers Builds**：GitHub 連携の **ビルド環境変数**に設定します。Worker 実行時だけの変数設定では、ブラウザー用アプリに入りません。
- 既存の `NODE_VERSION=24` やビルドコマンド `npm run build`、出力ディレクトリ `dist` は維持します。
- 値に引用符は付けず、そのまま入力してください。

プレビューにもログインを使わせる場合だけ、Preview 側の変数と Supabase のリダイレクト先 URL を設定してください。通常は本番だけで始められます。

## 6. 再デプロイする

環境変数を保存した後、**Deployments → 最新のデプロイ → Retry deployment / Redeploy** などから再デプロイしてください。設定変更だけでは、すでに公開されたアプリに反映されません。

ビルドでは Supabase の接続先だけを許可する CSP ヘッダーも生成します。アプリの公開 URL が変わっていなければ、既存の端末内データはそのまま残ります。

## 7. 初めてログインする

1. デプロイ完了後、アプリを再読み込みします。
2. 左上メニュー → **General → Account & sync（アカウントと同期）** を開きます。
3. **新規登録** でメールアドレスと12文字以上のパスワードを入力します。
4. 確認メールを開いて登録を完了し、アプリでログインします。
5. アカウントには、まず同梱の714問が用意されます。
6. これまでログインせずに使っていた端末では、同じ画面の **「この端末の記録を、このアカウントに追加する」** にチェックし、**「この端末の記録を追加する」** を押します。
7. **同期済み** になったことを確認します。

取り込みは問題番号を照合して学習履歴を追加します。同じIDの履歴、設定、難度はアカウント側を優先します。元のログイン前データもこのブラウザーに残り、ログアウトすると再び使えます。別の端末で作ったゲスト記録も、同じ操作で追加できます。

## 8. 別の端末で確認する

1. 別のスマホや PC で、同じ公開 URL を開きます。
2. **アカウントと同期** から、同じメールアドレス・パスワードでログインします。
3. 保存済みの記録が表示されます。

ログイン後の問題、履歴、模試、メモ、設定が同期対象です。変更はまず端末内へ保存し、接続でき次第同期します。別端末の更新は約15秒ごと、または画面に戻った際に確認します。必要なら **今すぐ同期** を押せます。

通信切断時は同期待ちになります。その端末・アカウントで再読み込みや再ログインしても記録は残ります。クラウドへの反映は **同期済み** を確認してください。

## 記録が競合したとき

2つの端末が、同じ古いデータからそれぞれ変更すると競合する場合があります。アプリは新しいクラウド記録を勝手に上書きせず、**「両方の記録を確認」** を表示します。

端末のバックアップを保存し、内容の置き換えを確認してから、**クラウドの記録を使う**、または **この端末の記録でクラウドを置き換える** を選びます。選ばなかった側の変更は自動で混ぜません。JSON バックアップは必要に応じて別途保管してください。

## よくある状態

| 表示・症状                   | 確認すること                                                             |
| ---------------------------- | ------------------------------------------------------------------------ |
| アカウントの準備中           | Cloudflare の2つのビルド環境変数と、設定後の再デプロイ                   |
| ログインできない             | メール・パスワード、確認メールの完了、Supabase の認証設定                |
| ログインできるが同期できない | SQL の実行、Supabase の稼働状態、接続先、ブラウザーの通信環境            |
| 端末の古い記録がない         | ログイン前データは独立しています。「この端末の記録を追加する」で取り込む |
| 別デバイスの変更がまだ出ない | 接続を確認し、「今すぐ同期」。元デバイスが同期待ちなら先にそちらを同期   |

ログイン情報は Supabase の SDK が管理します。JSON バックアップにはパスワードやログイン用トークンを含めません。共有端末ではログアウトし、必要に応じてブラウザーの保存データも管理してください。

アカウントを使わない動作、認証 API のテスト用応答を使った2端末同期、SQL のアクセス制御は開発環境で検証できます。本番のメール到達と実際の Supabase 接続は、この設定を完了してから確認します。
