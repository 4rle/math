# Focus Gold 学習管理 Web ツール仕様書

バージョン 1.0  
作成日 2026年10月25日  
用途 本書だけを渡して実装を進められるようにするための要件整理

## 1 目的と優先順位

Focus Gold に付属するチェック表を、問題番号の登録、学習結果の記録、取り組む候補の提示ができる Web ツールに置き換える。

当面の学習目標は、登録した対象問題の未着手をなくすこと。現在の中心は ☆3 と ☆4 の問題であり、解ける問題の短期的な反復に時間を使いすぎず、未着手問題に取り組んで解法を増やす。

主画面には、宇宙空間に浮かぶような多数の問題番号カードを画面いっぱいに配置する。カードをタップするとそのカードが手前に浮かび上がり、A〜E の理解度を選ぶだけで記録が完了する。

機能とデザインの優先順位は次のとおり。

1. 未着手問題を進めやすい。
2. 理解できていない問題や自力では解けない問題を見失わない。
3. 記録が少ない操作で終わる。
4. スマートフォンでも PC でも、番号と状態をすぐに読める。
5. 説明文、装飾、設定操作が学習画面を占有しない。

## 3 対象の参考書と問題

### 3.1 参考書

| 内部値 | 表示名 |
| --- | --- |
| `1A` | Ⅰ＋A |
| `2B` | Ⅱ＋B |
| `3C` | Ⅲ＋C |

参考書を切り替えたときは、その参考書の問題と学習状態を表示する。別の参考書で同じ問題番号を使っても混同しない。

初版では、各参考書についてユーザーが登録した番号を管理対象とする。Focus Gold 全問題の一覧や難度をシステム側で推測して生成しない。版による違いがある場合も、ユーザーの登録内容を正とする。

### 3.2 問題の識別

- 基本の重複判定は「参考書＋問題番号」で行う。
- ☆は問題の難度であり、A〜E はその人の学習結果である。別の属性として保存する。
- ☆を変更しても、同じ問題の学習履歴が分裂しないようにする。
- 初版は、一冊の中で番号が一意になる問題群を登録する運用を想定する。
- 将来、例題と練習など番号が重複する問題群を同時に扱う場合は、問題種別を識別項目に追加できる構造にする。この拡張は初版の必須機能ではない。

### 3.3 難度と単元

- 初版で必須の難度は ☆3 と ☆4。
- 主画面のカードにも、番号より控えめに `☆3`、`☆4` を表示し、難度を見分けられるようにする。
- ☆3のみ、☆4のみ、両方を表示する設定を用意する。
- この表示設定への入口はハンバーガーメニューに置き、主画面に難度選択バーを常設しない。
- 単元名は任意項目とする。未入力でも、登録、提示、記録が機能する。
- まだ学習対象にしていない参考書や単元まで消化するよう要求しない。進捗は登録済みの対象範囲について計算する。

## 4 主画面のデザイン

### 4.1 常設する要素

主画面で常に見える要素は、原則として次の3つだけにする。

1. 左上のハンバーガーメニューボタン。
2. 上部の参考書切り替えタブ。
3. それ以外の画面を埋める問題番号カードのフィールド。

参考書タブはコンパクトに配置し、大きな帯状ヘッダーを作らない。ロゴ、巨大なタイトル、紹介文、日付、学習統計カード、常設のサイドバーを追加しない。登録件数や進捗などの補助情報はメニュー内で確認できるようにする。

### 4.2 雰囲気

- 全体はダークテーマ。
- 奥行きのある暗い空間に、問題カードが多数浮いているように見せる。
- 背景の星や光は控えめにし、番号の可読性と操作を優先する。
- 強い光彩、派手な星雲、過剰なグラデーション、点滅、読み取りにくい透明パネルは避ける。
- カードは宇宙的な雰囲気に合わせつつ、作業に使う道具として番号と状態を明瞭にする。
- 過去の見本からは「選んだカードが手前へせり上がる動き」を引き継ぐ。ベージュの紙、実物の引き出し、トレーの外枠は最終画面の要件ではない。

配色の具体値は実装時に調整してよい。例として、背景は黒に近い紺、カードは背景より一段明るい暗色、本文は明るい灰色とする。カード全体を理解度ごとの強い原色で塗り分けない。

### 4.3 カードに表示する情報

カード上の情報の優先順位は次のとおり。

1. 問題番号を最も大きく表示する。
2. A〜E または未着手の状態を、小さな文字や印で表示する。
3. ☆3、☆4 を控えめに表示する。

単元、最終学習日、メモ、詳細な履歴は、カードを開いたときやメニュー内の詳細で表示する。全カードに長文の説明を載せない。

理解度の識別には色と文字を併用する。色だけを見ないと状態が分からないデザインにしない。例として、未着手は中立色、A は落ち着いた青、B・C は黄〜琥珀系、D・E は赤系の小さな印で表現する。D と E は文字でも明確に区別する。

### 4.4 多数のカードの配置

- デスクトップでもスマートフォンでも、フィールドを画面いっぱいに広げる。
- 今日の数問だけを大きく並べる画面にはせず、複数の候補カードが同時に浮いている状態を基本とする。
- カードの配置にはわずかな位置や奥行きの違いを付けてよいが、番号やタップ領域を他のカードで隠さない。
- 背景の動きとカードの操作を分離し、タップしようとしたカードが常に逃げるような動作を作らない。
- 表示枚数は画面の大きさに応じて変える。全問題を同時に極小表示することは求めない。
- 表示領域を超えたカードには、フィールド内の自然なスクロールやスワイプで到達できるようにする。別の大きなページ送り UI は常設しない。
- 常時の浮遊アニメーションを採用する場合は、ごく小さい動きに抑え、停止できるようにする。
- 大量のカードを扱ってもスクロールや選択が重くならないよう、必要に応じて描画範囲を制御する。

### 4.5 スマートフォンと PC

- スマートフォンの縦画面・横画面と PC のすべてに対応する。
- 横画面専用にはしない。
- 画面幅を使ってカード数を調整し、主要な文字や操作を縮めすぎない。
- スマートフォンのノッチやセーフエリアを避けてメニューとタブを置く。
- 通常のブラウザー表示で画面領域を有効に使う。ブラウザーの全画面 API を必須にしない。
- 参考書タブとメニューを操作しても、本文の大きなヘッダーや余白が追加されないようにする。

## 5 カードの選択と記録

### 5.1 基本フロー

1. ユーザーが問題番号カードをタップまたはクリックする。
2. そのカードが周囲より手前に移動し、少し拡大して浮かび上がる。
3. 選択中の問題番号と A〜E の選択肢を表示する。
4. ユーザーが A〜E のいずれかを選ぶ。
5. 学習結果を保存し、短い視覚的フィードバックを出してカードフィールドに戻る。

「取り組む」を押してから評価画面へ進む中間操作や、評価後の「完了」「保存」ボタンは設けない。A〜E の選択自体を完了操作にする。

問題は紙の参考書で解く。初版では問題文や解答をアプリに表示する必要はなく、問題番号と学習状態の管理に集中する。タイマーや解答入力も必須ではない。

### 5.2 選択時の表示

- 背景の他のカードを少し暗くし、選択中のカードを主役にする。
- 問題番号は選択後もすぐに確認できるようにする。
- A〜E は短いラベルだけでも違いが分かるようにし、必要なら補足を添える。
- スマートフォンでは縦並びなどを使い、5つの選択肢を小さく詰め込まない。
- 背景タップ、閉じる操作、PC の Escape キーで、未記録のまま戻れるようにする。
- キャンセルは学習済み扱いにしない。
- 評価の選択後は、保存の成功を確認してから閉じる。失敗した場合は閉じずに再試行できる状態を保つ。
- 誤操作を直せるように、直前の記録を取り消せる短い通知、または履歴から修正する機能を用意する。普段の記録で確認ダイアログは挟まない。

## 6 理解度の定義

| 状態 | 表示用の短い名称 | 判定基準 |
| --- | --- | --- |
| 未着手 | 未着手 | 学習結果をまだ記録していない |
| A | 自力完答 | 方針や解説を見ず、最後まで正しく解けた |
| B | 方針だけ確認 | 最初は迷ったが、解答の方針を一度見て、その後は閉じて解けた |
| C | 解説を少し確認 | 解説を部分的に確認しながら解けた |
| D | 解説を追って理解 | 解説を見ながら順を追って解けた。解説なしでの再現は未確認 |
| E | 解説でも不明 | 解説を見ても分からない箇所がある |

「見ただけで解けそう」という予想で A を付けることは想定しない。実際に自力完答した結果を記録する。自力で解けたが迷った場合も A にでき、余裕の有無を必須の追加評価にはしない。

ヒントを見た回は、その回の評価を B〜E として残す。同日に解説を閉じて解き直した結果を追加記録することはできるが、ヒントを見た履歴を自動的に消さない。

E の記録でも「一度は取り組んだ」ことにはなる。未着手ゼロと自力完答は別の指標として扱う。

## 7 学習候補の提示

### 7.1 未着手を優先する

- 基本方針は、登録した未着手問題を順番に進めること。
- 新規候補は、選択中の参考書と難度の対象範囲から選ぶ。
- 初期設定では問題番号の昇順を基本にする。
- 毎日、設定した数の新規候補をさりげなく目立たせる。初期値案は3問。
- これは「今日取り組む目安」であり、他のカードを選べなくする制限にはしない。
- 新規候補の件数を達成しても、残りの未着手カードにはアクセスできる。
- その日の新規件数には、初めて A〜E の結果を記録した問題だけを数える。復習の記録は新規件数に加えない。
- 日付が変わっても学習状態を未着手に戻したり、同じ問題を重複登録したりしない。
- 一日の件数管理は日本時間を基準にする。

主画面には多数のカードを表示しつつ、今日の新規候補はわずかな明度差や位置などで見分けられるようにする。大きな「今日のノルマ」パネルは作らない。

### 7.2 復習候補の初期設定案

| 最新状態 | 通常時の扱い | 候補にする時期の初期値案 |
| --- | --- | --- |
| A | 通常の復習対象から外し、模試前まで保留 | 模試前モードに入ったとき |
| B | 新規問題とは別に、復習候補として扱う | 実際に解いた日から14日後 |
| C | 自力で解き直す候補として扱う | 実際に解いた日から7日後 |
| D | 解説を閉じて再現する候補として扱う | 実際に解いた日から7日後 |
| E | 要再学習として見失わないようにする | 日数待ちではなく、記録後から候補として参照可能 |

- 翌日の自動復習を初期値にしない。
- 日数は設定で変更できるようにする。
- これらは期限ではなく、復習候補に加わる日である。
- 候補になった復習は、新規問題を進める流れに強制的に割り込ませない。
- 候補の日を過ぎても「延滞」「失敗」などの表示をしない。
- 放置した日数に比例して、同じ問題のカードが増殖することはない。
- 次回候補日は、予定日ではなく実際に記録した学習日から計算する。
- B〜E から A になったら、その時点で通常の復習提示から外す。

### 7.3 E の扱い

E は単なる「忘れた問題」ではなく、理解を補う必要がある状態として扱う。

- カードに E または要再学習の印を付ける。
- 未着手カードを主役にしつつ、E の存在も分かるように配置する。
- E が大量にあっても、表示枠をすべて E で埋めて新規問題を見えなくしない。
- 分からない式変形、発想、前提知識などを短くメモできるようにする。メモは任意で、記録の必須手順にはしない。
- 基本問題の確認や質問などで理解を補った後、再び A〜E を記録できる。
- 毎日同じ問題を強制的に解き直させる運用にはしない。

### 7.4 理解度と経過日数を分ける

- 最新評価と最終学習日を別々に保持する。
- 最終自力完答日も別に保持する。
- 日数が経っただけで A を C・D・E に変更しない。
- A のカードを日数だけで危険色に変えない。
- 「最終自力完答から45日」などの情報は詳細で確認できるようにする。
- 初版では、データの根拠がない「忘却確率」「理解度87%」などの精密そうな数値を生成しない。

## 8 模試前の確認

### 8.1 模試の登録

ハンバーガーメニューから、次の情報を手入力できるようにする。

- 模試名。
- 実施日。
- 対象の参考書。
- 対象の難度。
- 対象単元または問題番号範囲。細かく指定しない場合は、その参考書の登録済み対象問題全体。
- 確認を始める日、または模試の何日前から始めるか。

開始時期の初期値案は14日前とする。この日数に学術的な最適値という意味を持たせない。

Google カレンダーとの同期は初版の必須機能にしない。後から連携できる余地は残すが、模試の登録やカード提示を外部サービスへの接続に依存させない。

### 8.2 模試前モード

- 設定した期間に入ったら、範囲内の A も確認候補に戻す。
- このときも、A の理解度を自動的に下げない。
- A の中では、最後の自力完答が古い問題や、過去に C〜E だった問題を先に確認できるようにする。
- 全ての A を必ず解き直すノルマにはしない。
- 模試前の確認でも、記録操作は通常と同じ「カード選択→A〜E」で完結させる。
- その模試の確認期間内に A として確認できた問題は、同じ模試に対して何度も確認候補に出し続けない。
- 模試前の確認で B〜E になった場合は、最新状態に応じた通常の扱いに戻す。
- 模試が終わったら、その模試に由来する A の提示を終了する。学習履歴は消さない。
- 模試の日付だけを登録する初版では、実施日を確認期間に含め、翌日の日本時間00時にその模試前モードを終了する。
- 複数の模試がある場合は、どの模試の範囲や期間に該当しているかを内部で区別する。

モードの状態や模試の詳細はメニュー内で確認する。主画面に大きなカウントダウンや専用ヘッダーを追加しない。

## 9 問題の登録

### 9.1 手入力

ハンバーガーメニューから問題登録を開く。

1. 参考書を選ぶ。
2. ☆3 または ☆4 を選ぶ。
3. 問題番号をまとめて貼り付ける。
4. 読み取った番号と件数を確認して登録する。

入力例。

```text
125, 128, 132, 140
```

カンマ区切り、改行区切り、空白区切りを受け付け、全角数字と全角カンマは必要に応じて正規化する。空欄や区切り文字だけの入力は問題として作成しない。初版で扱う問題番号は正の整数とする。

同じ番号の重複は確認時にまとめる。既存問題があっても、学習履歴を勝手に初期化しない。

### 9.2 CSV 取り込み

最低限の列は `book`、`stars`、`number` とする。

```csv
book,stars,number
1A,3,125
1A,4,128
2B,3,42
3C,4,61
```

任意の `unit` 列で単元名を追加できるようにする。

```csv
book,stars,number,unit
1A,3,125,登録した単元名
1A,4,128,登録した単元名
```

- UTF-8 の CSV と BOM 付き UTF-8 を受け付ける。
- ヘッダーにより列を対応付け、列順だけに依存しない。
- 空行を除外する。
- 参考書の値、難度、問題番号を検証する。
- 取り込み前に、参考書別・☆別の新規件数、既存重複、入力エラーを表示する。
- 同じ参考書・番号で ☆が食い違う場合は、履歴を維持したうえで難度を更新するか確認できるようにする。
- エラー行は行番号と理由を示し、黙って別の問題番号に置き換えない。
- 登録一覧の CSV は新規問題を追加する用途とする。学習履歴まで含めた完全復元は別のバックアップ形式で扱う。

### 9.3 写真から CSV を作る流れ

写真を AI に渡して、番号と ☆を抽出し、CSV として取り込む運用を想定する。

1. 番号と難度が分かるチェック表などを撮影する。
2. AI に、上記の CSV 形式で抽出させる。
3. 読み取れない箇所は確認対象として残す。
4. ユーザーが元の写真と照合する。
5. 確認済みの CSV をアプリに取り込む。

初版では、外部の AI で作った CSV を取り込めればよい。アプリ内で写真を送信・解析する機能は将来拡張とし、外部 API や認証を初版の必須条件にしない。

写真解析では、番号の取り違え、☆の取り違え、行の抜け、別の問題種別の混入に注意する。判読できない番号を推測して確定しない。

## 10 ハンバーガーメニュー

左上のメニューボタンから、設定や管理に関する機能へアクセスする。メニューを閉じた状態では、その機能群は学習画面を占有しない。

| メニュー項目 | 内容 |
| --- | --- |
| 問題の登録と管理 | 手入力、CSV 取り込み、登録一覧の編集 |
| 表示する問題 | ☆の選択、単元、候補表示または全登録問題の確認 |
| 学習の設定 | 新規候補数、B・C・D の復習候補日数 |
| 模試 | 模試の日程、対象範囲、確認開始時期 |
| 学習履歴 | 記録の確認、評価やメモの修正 |
| 進捗 | 未着手数、取り組み済み数、自力完答数、状態ごとの件数 |
| データ | バックアップの書き出しと復元、登録一覧の CSV 出力 |
| 表示と動き | 浮遊アニメーションの停止など |

設定画面は必要に応じてスクロールしてよい。主画面を簡潔に保つことを優先する。設定を開くためのボタンを画面の各所に重複配置しない。

## 11 保存する情報

### 11.1 問題

| 項目 | 内容 |
| --- | --- |
| `id` | 変わらない問題 ID |
| `book` | `1A`、`2B`、`3C` |
| `number` | 問題番号 |
| `stars` | 問題の難度 |
| `unit` | 任意の単元名 |
| `latest_grade` | 未着手の場合は未設定、それ以外は A〜E |
| `last_attempt_at` | 最後に結果を記録した日時 |
| `last_self_solved_at` | 最後に A を記録した日時 |
| `review_available_on` | 復習候補に加わる日。A と E では通常の間隔計算に使わない |
| `memo` | 任意の短いメモ |
| `created_at` | 登録日時 |

### 11.2 学習履歴

問題ごとに、問題 ID、記録日時、評価、任意のメモを保持する。最新状態だけで過去の記録を上書きしない。履歴から「以前 E だったが、現在は A」などが分かるようにする。

### 11.3 模試と設定

模試の日程、対象範囲、確認開始時期、模試前確認の実施状況を保存する。新規候補数、復習候補日数、表示対象、アニメーション設定も保持する。

日時は比較しやすい形式で保存し、日単位の候補判定や表示は日本時間を基準にそろえる。

## 12 保存と端末の扱い

### 12.1 必須

- 再読み込みやブラウザーの再起動後も、問題と履歴を保持する。
- 記録の保存が終わる前に、成功したように画面から消さない。
- 全問題、学習履歴、模試、設定を含めたバックアップを書き出せるようにする。
- バックアップから復元できるようにする。
- 復元時は、既存データを置き換えるかどうかが分かる画面を出す。
- 問題登録 CSV の再取り込みで学習履歴を消さない。

### 12.2 初版の構成案

ログインなしで使い始められる構成を初期案とする。端末内保存には IndexedDB などを利用し、完全バックアップは JSON などの形式で書き出す。

「スマートフォンと PC の両方で使えること」と「端末間で履歴が自動同期されること」は別の要件である。前者は必須。後者は未確定で、初版ではバックアップの受け渡しで対応する案とする。端末内保存を自動同期のように説明しない。

フレームワーク、ホスティング先、クラウド保存、認証方式は本書では固定しない。PWA としてのインストール対応も、現時点では必須にしない。

## 13 状態と例外処理

| 状態 | 必要な動作 |
| --- | --- |
| 問題が未登録 | 小さな空状態の案内を出し、メニューから登録できるようにする |
| 選択した ☆の問題がない | 表示対象に問題がないことを示し、他の難度の問題を勝手に混ぜない |
| 新規候補を解き終えた | 他の未着手問題や復習候補を引き続き選べる |
| 登録問題の未着手がなくなった | 新しい問題を捏造せず、復習候補を選べる状態にする |
| A だけが残っている | 通常時は完了状態を示す。全登録問題の確認と模試設定にはアクセスできる |
| 候補が多い | 読めるサイズを維持し、スクロールや描画範囲の制御で対応する |
| 保存に失敗した | 評価画面を閉じず、選択結果を保持して再試行できるようにする |
| CSV が不正 | 問題のある行と理由を示し、既存履歴を維持する |
| 記録を間違えた | 取り消しまたは履歴修正により、状態と候補日も整合するよう戻す |

空状態の案内は例外時だけ表示する。通常画面に説明文を残し続けない。

## 14 操作性と動き

- カードと評価ボタンは、タッチでも押し分けられる大きさにする。主要なタップ領域は44 CSS px程度を目安に確保する。
- 問題番号、状態、評価ラベルはダーク背景に対して十分なコントラストを確保する。
- 色だけに依存しない。
- PC では Tab キーで操作対象を移動し、Enter または Space で選択できるようにする。
- 選択画面のキーボードフォーカスは適切に管理し、閉じたら元のカードに戻す。
- ホバーしないと番号や操作が分からない作りにしない。
- カードを拡大する動きは短く、操作結果が分かるものにする。
- OS の動きを減らす設定と、アプリ内のアニメーション停止設定に対応する。
- 星やカードの点滅、強いカメラ移動、長い演出で記録を待たせない。
- 横画面、縦画面、文字サイズの拡大でも、評価や閉じる操作に到達できるようにする。

## 16 受け入れ条件

実装完了時には、少なくとも次の動作を確認する。

1. 主画面には、メニューボタン、参考書タブ、カードフィールドだけが常設されている。
2. スマートフォンと PC のいずれでも、ダークな空間に多数の番号カードが浮かぶ画面になっている。
3. 番号を読めないほどカードが縮小したり、他のカードと重なって操作できなくなったりしない。
4. カードを選ぶと手前に浮かび上がり、A〜E の選択だけで保存が完了する。
5. 評価を選ばず閉じたときは、未着手や最新評価が変更されない。
6. Ⅰ＋A の125番と Ⅱ＋B の125番が別の問題として扱われる。
7. ☆3と☆4を別々に登録でき、カード上でも難度が分かる。
8. CSV の重複登録で、過去の学習履歴が消えない。
9. 未着手がある場合、通常の候補選びは未着手を優先し、復習を強制しない。
10. 初期設定では C・D を記録した翌日に自動復習を要求しない。
11. A を記録した問題は、通常の復習候補から外れる。
12. A は時間経過だけでは低評価や危険色に変更されない。
13. E は要再学習として確認できるが、未着手カードを全て押しのけない。
14. 登録した模試の確認期間に入ると、範囲内の A が候補に戻る。
15. 模試前に A として確認済みの問題を、同じ模試向けに何度も提示し続けない。
16. 未着手ゼロと自力完答の件数が別々に確認できる。
17. 再読み込み後も、評価、履歴、模試、設定が維持される。
18. バックアップを復元したときに、履歴と候補日の関係が保たれる。
19. 記録の取り消しで、誤った最新評価や候補日が残らない。
20. 動きを減らす設定でも、カード選択と記録が支障なく行える。

## 17 研究に基づく背景と限界

数学でも、練習を日を分けて配置することには長期保持上の利点が報告されている。一方、Focus Gold の ☆3〜4 と本書の A〜E に対応した最適な復習日数が、直接検証されているわけではない。

本ツールでは、新しい解法を増やすために未着手を優先し、自力完答した問題は模試前まで通常の復習から外す方針を採用する。これはユーザーが選んだ学習運用であり、「一度解けたら忘れない」「模試まで復習しないことが万人に最適」という研究上の結論として説明しない。
